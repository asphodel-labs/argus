# argus: a TUI for GitHub PR management and review

## Overview
- argus is a Go terminal UI that shows open pull requests and lets the user act on them with vim-style keys.
- The left pane lists PRs: PRs that need my review, my PRs grouped by repository, PRs in my organisations, and PRs in my personal repositories.
- The main pane shows one PR: title, status, CI checks, description, and conversation threads.
- Actions: approve, merge, rerun checks, comment, reply, react, resolve threads.
- Review: `v` opens revdiff for the PR in an agterm overlay and posts the annotations as one GitHub review. `p` opens a Claude session with `/pr <url>` in a new agterm session.
- A background poller refreshes the data and sends agterm notifications for review requests, activity on my PRs, and CI results on my PRs.
- argus uses the local `gh` authentication. It needs no separate token.

## Context (from discovery)
- The repository is empty. The remote is `git@personalgit:tdragon/argus.git`. The Go module path is `github.com/tdragon/argus`.
- Installed tools: `gh` 2.103.3, Go 1.27.3, `agtermctl`, `revdiff`.
- revdiff annotation output format (stable since revdiff v1.0.0, from its CHANGELOG and README):
  - `## path:L (+)`, `## path:L (-)`, `## path:A-B (+)`, `## path (file-level)`, then the comment body.
  - A body line that starts with `## ` gets one leading space.
  - `--exit-code-on-annotations` makes revdiff exit with code 10 when it writes annotations.
- agtermctl:
  - `session overlay open --block` waits until the command exits and exits with its status.
  - `session new --workspace-name --create-workspace --cwd --name --command` makes a session.
  - `notify <body> --title --target` posts a notification.
  - A shell in agterm gets `AGTERM_SESSION_ID`.

## Solution Overview
- Single TUI process (approach A from the brainstorm). The poller runs in a goroutine inside the TUI.
- The poller package has no TUI imports. A later headless `argus watch` mode can reuse it. That mode is out of scope for v1.
- Stack: Bubble Tea v2, Lip Gloss, Bubbles (list, viewport, textarea), `github.com/cli/go-gh/v2`, Glamour, a TOML library.
- Packages:
  - `cmd/argus/`: parse flags, load config, start the TUI.
  - `internal/config`: TOML config at `~/.config/argus/config.toml`.
  - `internal/gh`: GraphQL queries and mutations, REST for notifications and reruns.
  - `internal/model`: PR, Check, Thread, Review, and the derived Status.
  - `internal/poller`: timer, notifications check, full refresh, snapshot diff to events.
  - `internal/notify`: events to `agtermctl notify`, with the seen state.
  - `internal/review`: worktree setup, revdiff run, annotation parse, review submit.
  - `internal/launch`: Claude session through `agtermctl session new`.
  - `internal/tui`: list pane, detail pane, dialogs, status bar.
- State directory: `~/.local/state/argus/` holds `seen.json`, the annotation files, and the last merge method for each repo.

## Technical Details

### Config (`config.toml`)
```toml
orgs = ["acme"]
user = ""                 # empty: read the login from gh
refresh_interval = "10m"
min_refresh_gap = "5m"    # minimum time between refreshes that notifications start
repo_root = "~/sources"   # clone lookup: <repo_root>/<owner>/<repo>
bot_logins = ["renovate-bot"]

[repos]                   # optional overrides
"acme/api" = "~/work/api"

[colors]                  # optional; ANSI number or #rrggbb
approved = "2"
```

### Search scopes
| Scope | Query | Limit |
|---|---|---|
| Needs my review | `is:pr is:open review-requested:@me` and `is:pr is:open assignee:@me`, merged by PR id | all pages |
| My PRs | `is:pr is:open author:@me` | all pages |
| Each org | `is:pr is:open org:<org> sort:updated-desc` | 20, `m` loads 20 more |
| Personal | `is:pr is:open user:<me> sort:updated-desc` | 20, `m` loads 20 more |

- A section footer shows `… N more  [m] load more`. N comes from `issueCount` minus the loaded count.
- A background refresh fetches the same number of PRs that the user loaded. It does not reset to 20.
- Each search requests `rateLimit { cost remaining resetAt }`.
- Measured cost (2026-11-16): one search page of 20 costs 11 points, one page of 100 costs 54 points. Thus `SearchAll` reads pages of 20.

### Status rules (first match wins)
| Icon | Status | Rule | Color |
|---|---|---|---|
| ✗ | CI failed | rollup FAILURE or ERROR | red |
| ✎ | Changes requested | reviewDecision CHANGES_REQUESTED | yellow |
| 💬 | Needs reply | unresolved thread whose last comment is not mine | yellow |
| ◌ | Draft | isDraft | gray (dim) |
| ⊘ | Conflict | mergeable CONFLICTING | red |
| ⏳ | Pending review | no decision, CI pending or green | blue |
| ✓ | Approved | APPROVED and CI green | green |

- The brainstorm table listed Conflict last. Conflict is placed before Pending review here, because otherwise it never matches: Pending review or Approved catch every remaining PR. Task 2 confirmed this order.
- A PR that matches no rule (for example APPROVED with CI pending) gets Pending review. A rollup with no checks counts as green. `REVIEW_REQUIRED` and an empty decision both count as no decision.
- Colors use the 16 ANSI colors. Each color has an icon, so the status stays clear without color.

### Events (snapshot diff for each PR id)
| Event | Rule |
|---|---|
| Review requested | PR is new in the review-requested scope or in the assignee scope |
| Activity on my PR | comment, review, or thread count went up, and the newest author is not me |
| CI result on my PR | rollup changed from PENDING to SUCCESS, FAILURE, or ERROR |

- argus sends at most 5 notifications for each refresh. The remainder becomes one summary line.
- The first run with no `seen.json` records the state and sends no notifications.

### Poll loop
1. Every 60 s, or the `X-Poll-Interval` value, send `GET /notifications` with `If-Modified-Since`. A `304` reply costs no rate limit.
2. Run a full refresh if the reply is `200` with new threads, if `refresh_interval` elapsed, or if the user pressed `ctrl+r`.
3. On a failed refresh, keep the last snapshot. Retry after 1, 2, 4, and at most 10 min.
4. If `rateLimit.remaining` < 200, pause the full refresh until `resetAt`.
5. A full refresh that a `200` from `/notifications` starts runs only when `min_refresh_gap` passed since the start of the last full refresh. Inside the gap, the refresh is due and runs at the end of the gap. The `refresh_interval` refresh, `ctrl+r`, and `m` (load more) skip the gap. One search page of 20 costs 11 points (task 3).

### Review flow
1. Find the clone: the `[repos]` override, then `<repo_root>/<owner>/<repo>`. If no clone exists, ask before `gh repo clone`.
2. `git fetch origin pull/<n>/head` and the base branch.
3. `git worktree add --detach <clone>/.worktrees/argus-pr-<n> <headSha>`. Move an existing worktree to the new head only if its tree is clean.
4. Compute `<merge-base>` with `git merge-base origin/<base> <headSha>`. Write the PR body to `<state>/pr-<owner>-<repo>-<n>.body.md`.
5. `v` runs in a background `tea.Cmd`:
   ```
   agtermctl session overlay open --block --target $AGTERM_SESSION_ID --cwd <worktree> \
     "revdiff --vim-motion --exit-code-on-annotations -o <state>/pr-<owner>-<repo>-<n>.md \
        --description-file <body.md> <merge-base> <headSha>"
   ```
   - Exit 10: parse the annotations and open the review dialog.
   - Exit 0: do nothing.
   - Other: show the error in the status bar.
   - If the annotation file exists from a failed submit, add `--annotations <file>`.
6. Annotation mapping. Each thread is one `addPullRequestReviewThread` call:

   | revdiff record | `addPullRequestReviewThread` input |
   |---|---|
   | `path:L (+)` | `line: L, side: RIGHT` |
   | `path:L (-)` | `line: L, side: LEFT` |
   | `path:A-B (+)` | `startLine: A, line: B, side: RIGHT` |
   | `path (file-level)` | `subjectType: FILE` |

   - The `threads` input of `addPullRequestReview` (`DraftPullRequestReviewThread`) has no `subjectType` field (checked with schema introspection on 2026-11-16). Thus argus does not use it.
7. Hunk check before the submit. Parse the hunk ranges from `git diff <merge-base> <headSha>`. A line comment outside every hunk of its side moves into the review body as `path:L — text`. The dialog marks these comments.
8. Submit sequence:
   1. Find my pending review on the PR. If none exists, make one with `addPullRequestReview(pullRequestId, commitOID: headSha)` and no event.
   2. Add each thread with `addPullRequestReviewThread(pullRequestReviewId, ...)`.
   3. Submit with `submitPullRequestReview(pullRequestReviewId, event, body)`.
   - If the PR head moved after the checkout, show a warning in the dialog.
   - On a failure, keep the annotation file. On a success, delete it and the body file.
   - If a step fails after step 1, the pending review stays on GitHub. The next submit finds it in step 1 and adds to it. ⚠️ A retry after a failure in step 2 can add a thread two times. Check during task 14 whether the threads already on the pending review must be compared by path, line, and body.
9. On start, list the `argus-pr-*` worktrees and fetch the state of their PRs with one GraphQL query. Remove a worktree whose tree is clean and whose PR is merged or closed. Never remove a worktree with changes.

### Keys
- Global: `j`/`k`, `gg`/`G`, `ctrl+d`/`ctrl+u`, `]`/`[`, `za`, `/` with `n`/`N`, `ctrl+r` refresh, `?` help, `q` quit, `tab` or `h`/`l` pane focus, `esc` closes a dialog.
- List pane: `a` hide approved, `d` hide drafts, `b` cycle bots (all / only bots / no bots), `u` author picker, `m` load more.
- Detail actions (both panes, act on the selected PR): `A` approve, `M` merge, `f` rerun failed, `F` rerun all, `c` comment, `r` reply, `+` react, `x` resolve, `o` browser, `p` Claude, `v` revdiff.
- `q` asks for confirmation if a dialog has unsent text.
